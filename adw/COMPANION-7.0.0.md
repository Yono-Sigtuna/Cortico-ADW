## 1. 它是什么

不是"一个陪聊插件"，是**二十个领域叠起来的数字人运行时**：1945 个文件、约 600 万字节 Python、36 个子包。

插件自己的 `product/CORE_COMPONENTS` 把产品分成八块：

| 组件 | 一句话 |
|---|---|
| conversation | 私聊、群聊、多账号多人格、消息合并与安全投递 |
| identity_relationships | 安装、角色、对象权限、关系背景、可审阅的关系记忆 |
| memory | 有来源的事实、经历、检索、反思、修订、遗忘边界 |
| life_journal | 日程、阅读、睡眠、日记、梦境、成长、角色时间线 |
| media_sources | 图片、音频、视频、引用、转发、来源证据 |
| proactive_tasks | 主动联系偏好、日程触发、任务监督、额度与恢复 |
| capability_room | 能力注册、授权、配置投影、体素小屋 |
| diagnostics | 运行证据、诊断建议、修复确认、停机恢复 |

## 2. 三条主链

### 2.1 回复链（普通说话）

AstrBot 核心管线负责模型、历史、工具循环与发送；V2 只在请求前后"贴边"：
- 入站：认领 → 对话开关 → 私聊权限 → 群参与检查；
- 前置：背景（关系/记忆/生活/灵感）逐节降级读取，不调模型；
- 请求：把人设与感知合并成一个当轮 user 块，不污染系统提示缓存；
- 发送前：分段、语音策略、图片位置、组件排序、群引用/@、**收尾判断**；
- 记录：原生输入/输出/发送回执分别入库。

群参与有一张优先级表（mention → quote → wakeup → direct word → followup → …），但它只是**候选**，最终由模型调 `group.participation.choose` 决定 reply/skip。

**收尾判断只作用于私聊**：当前消息是纯收尾词，且角色 30 分钟内已发过强收尾（或用户连续两次收尾），才静默；否则只加提示。

### 2.2 主动链（她自己开口）

```
机会（Opportunity，带 opened_at / expires_at）
  → 念头（Thought，多个候选，带权重）
  → 计划（DeliveryPlan，按稳定种子确定性选择）
  → 模型生成（decision: send|skip + confidence + 正文）
  → 人格判定（可选第二模型：这条像不像我）
  → 表达复核（可选：学到的句式是否生硬）
  → 投递（分段、语音、表情、戳一戳）
```

机会由 **20 个生产者**供给，分两类：
- **她自己的生活**：活动完成、成长进展、日记、回忆、约定、起床、早晚问候、纪念日、饭点、关系排期、屏幕观察；
- **外部信息**：新闻、天气、天气变化、官方预警、服务余额。

节奏只收紧不放宽：小时活动曲线、强度档位、burst 连发窗口、分享概率、收尾静默、24h 硬配额。忙碌门（日历命中活动词）延迟而非丢弃，绝不 sleep。

### 2.3 生活链（她有自己的日子）

- **状态**：11 个字段（精力/饥饿/健康/睡眠/忙碌/心情五轴/位置/周期/公开状态/在线态/临时状况），后台模型定期维护，只影响语气浓度；
- **日记/梦境**：第一人称私人书写，素材来自当天活动与对话；梦不是现实；
- **成长**：技能与长期目标账本，必须有人类确认，不做数值等级；
- **日程**：计划/约定/提醒，Memorandum 分 note 与 open_loop，提醒走独立投递。

## 4. 对照 Cortico：已有 / 缺 / 不搬

Cortico 的底座其实相当好：**事件流是真源、文件工作区进 git、记忆是可重建的投影、梦是整理线程、权限矩阵明确**。它缺的不是"存储"，是"她自己的生活"。

| 插件能力 | Cortico 现状 | 判断 |
|---|---|---|
| 角色状态（11 字段） | 无 | **补**（M29 已落地精简版：精力/心情五轴/睡眠/忙碌/健康/公开状态/在线态/临时状况） |
| 日记/梦境 | 梦有整理，无私人书写 | **补**（M29：梦写 `memo/diary/`，主意识当天看一次） |
| 关系记忆（她的看法） | 只有 `people/` 档案与结构化字段 | **补**（M29：`## 我的看法`，带日期、可改写；完整 proposed/reviewed 状态机暂缓） |
| 主动联系 | 无 | **补**（M28：机会/念头/计划 + 未完话头 + 问候） |
| 收尾判断 | 无 | 暂缓：部署没有私聊，插件也只对私聊生效 |
| 忙碌门 | 无日历 | 部分：状态里的 `busy` 可作为主动联系的软闸，后续接 |
| 群参与候选评分 | World 层只有唤醒词 | 后续：把候选理由映射成唤醒评分 |
| 表达学习 / 表情库 | 无；发图 0 次 | 不搬：ROI 低，且样本治理成本高 |
| 记忆的证据链与撤销 | 只有 `source` 字符串 | 后续：这是插件最值得学的工程纪律 |
| 日程/提醒/日历 | 无 | 后续：复用 `core.timers`，成本最高但价值高 |
| 成长账本 | 无 | 后续：依赖日记与活动回执，先有素材 |
| 游戏/空间/直播/识屏/现实/一起/生图/创作 | 无 | 不搬：与"她像个人"弱相关，且各自都是独立产品 |
| Laya 决策模型 | 无 | 不搬：第二个模型 + 额外部署；沉默可以用规则+主模型表达 |
| 人格工坊 | 无 | 不搬：Cortico 的宪法与语气卡已经是工坊 |

## 5. 本次落地（M29）

1. **角色状态** `companion/roleState.ts`：存储 + 规则漂移（心情半衰期 180 分钟、精力按昼夜）+ 渲染；梦用 `maintain_state` 工具写，主意识每轮看到一段「你自己此刻的状态」。
2. **日记** `companion/life.ts`：梦写 `memo/diary/YYYY-MM-DD.md`；主意识当天第一次醒来时看到最近一篇的一段。
3. **她的看法** `people.ts` 的 `## 我的看法`：梦维护 2–4 条带日期的判断；这个人开口时，看法和档案、曾用名一起进上下文。
4. 三条都遵守同一条纪律：**只影响语气与判断的连续性，不播报数值，不冒充事实**。

## 6. 后续优先级（按"她变好的幅度 ÷ 成本"）

1. **跨窗口觉察**：这个人 12 分钟前在群里说过什么、你们上次私聊是什么时候——成本 1–2 个文件。
2. **未完话头升级**：支持"用户明确留下的话头"（不是她自己的提问），带过期与修订。
3. **记忆证据链**：`remember` 必须带来源（事件游标或文件名），并支持撤销 → 回答"你凭哪句话记住的"。
4. **忙碌门**：用状态里的 `busy` 与作息决定主动联系是否延后。
5. **日程/提醒**：约定、提醒、过期处理。
6. **成长账本**：从日记与活动里提取技能/目标进展，必须人工确认。
