# Design: 控制台事件窗口 —— 时间、图标与提示浮层

Generated by /office-hours on 2026-10-28
Repo: C:\Cortico\Cortico-main（非 git 检出）
Status: APPROVED（2026-10-28，已实现）
Mode: Builder

## Problem Statement

查"她为什么这么答"时，控制台时间线把**一次唤醒**拆成了两块互不相连的东西：

```
USER   [记忆] ……            ← 这一轮注入给她的全部内部提示
       [时间] 距上次和你说话：3 小时。    揉成一段纯文本，
       [动作] 动作不是表演……              没有类型、没有逐条时间
tool   external_event_frame  ← 这一批外部事件
       [3 new events]
       14:31 大肥鱼: 小克你在干嘛
```

时间其实一个都不缺：`context.frame.events[]` 里每条都带 `ts / type / source / cursor / start / chars`（[src/core/loop.ts:854](C:/Cortico/Cortico-main/src/core/loop.ts:854)），只是 [timeline.ts](C:/Cortico/Cortico-main/src/web/client/features/live/timeline.ts) 没画。缺的是另一半：注入提示在 [loop.ts:699-708](C:/Cortico/Cortico-main/src/core/loop.ts:699) 合并成一条 user 消息时只剩文本，"哪一行是 gesture、哪一行是 memory、各是几点进的"全丢了。结果是每次追因都要去 `session-main.jsonl` 里数行。

## What Makes This Cool

把一个"她为什么这么说"的追问，变成鼠标停一下就有答案的动作：头部一句 `14:32:05 · 3 条事件 · 7 条提示`，浮层里按注入顺序列出这一轮她真正看到的东西，点一条复制出来就能贴进对话复现。

## Constraints

- **不改 session 正文**、不改 token 计数、不改模型可见内容。只加 `context` 上的元数据（P4）。
- 时间必须是事件自带的 `ts`，不能在前端重新打点。
- 四条入口/路径必须同形状：`f.session`、`f.messages`、`rebuild()`（整份重画／轮询）、`append()`（实时帧）。
- 一次唤醒的注入可能**没有**外部事件帧（内部唤醒），不能因此被吞掉。
- `eventDelivery() === 'user'` 模式下**不存在** `external_event_frame` 调用（[loop.ts:710](C:/Cortico/Cortico-main/src/core/loop.ts:710) 只在 `!inUser` 时 `appendEventFrame`），注入与事件都在同一条 user 消息上。
- 元数据可能**失效或缺失**：`rebuildTail()` 折叠超长回执、`bootstrap()` 补 `MISSING_RESULT_RESTART`、`fixPairing()` 修配对，都会产生没有 `frame`、或 `frame` 指向被替换后文本的记录。
- 前端测试跑在迷你 DOM 桩上（[tests/web/feature-live.test.ts](C:/Cortico/Cortico-main/tests/web/feature-live.test.ts)），`FakeEl` 没有 `getBoundingClientRect`。
- locale：`strings.ts` 的 `zh` 是基准类型，`en` 是 `typeof zh` 的完整镜像——新键两处都要加；其余语言是 `Partial`，缺失自动回落，不必逐个补。

## Premises

1. **「窗口事件」= `external_event_frame`**：一次唤醒一个合成调用+回执，不是每条 QQ 消息一个。— 已确认
2. **「携带的 prompt」= 这一轮注入的内部提示**（memory / gesture / budget / time / state / thread / ground / diary / life / emergence），不是系统前缀。— 已确认
3. 现在这些提示合并成一条 user 消息、没有逐条 kind 和时间，所以服务端必须补元数据才能逐条展开。— 已确认
4. 只在控制台可见，不进 session、不影响她的上下文。— 已确认

## Approaches Considered

- **A 纯前端压缩**（否决）：只改 `timeline.ts`，按相邻关系把事件帧前那条 USER 块拆行显示。零服务端改动，但拿不到逐条 kind 与各自时间，且内部唤醒没有帧会落单、配对靠猜。
- **C 逐条独立渲染**（否决）：每条注入各自成行、自带时间与图标，不需要配对。代价是一次唤醒在 session 里多出 6–8 条记录，文件与 message 计数持续变大，`ephemeral` 语义要重排。
- **B 补 internals + 事件窗口**（选定）。

## Recommended Approach

### 0. 数据在哪（先把这一点钉死）

| 数据 | 落在哪条记录 | 位置 |
|---|---|---|
| 注入提示的逐条位置 | 合并后的 `user` 消息 | `context.internals[]`（本次新增） |
| 已投递事件的逐条位置 | `function_call_output`，**不是** `function_call` | `context.frame.events[]`（已有） |
| 事件正文 | 同上回执的 `output` | 与 `frame.events[].start/chars` 对应 |
| 记录自身时间 | 任意记录 | `context.ts`（已有，可缺席） |

`appendEventFrame()` 里 `functionCall()` 不带任何 context，`functionResult()` 才带 `frame`（[loop.ts:847-856](C:/Cortico/Cortico-main/src/core/loop.ts:847)）。所以**窗口头部不能在建 `function_call` 时就定时间**，必须等回执到达再回填。

### 1. 服务端：给那条合并消息补 `internals`（约 4 行）

`src/protocol/open-responses/context.ts` — `ContextMeta` 增加一个字段，复用现有 `FrameEventRef`：

```ts
/** 这一轮注入的内部提示，逐条位置；与 frame.events 分开，便于控制台分两组显示。 */
internals?: FrameEventRef[];
```

`frameEventRefs(events, base)`（[loop.ts:201-209](C:/Cortico/Cortico-main/src/core/loop.ts:201)）已把每段 `text` 的 `start / chars` 按换行累加算好，内部文本的拼接方式完全相同（`lines.join('\n')`），直接复用、起点 0：

```ts
if (internals.length > 0) msg.context.internals = frameEventRefs(internals, 0);
```

`inUser` 模式下 `context.frame` 的 `base` 是内部行总长，两者天然不重叠。`internals` 是纯元数据：不进请求体（`inputItem()` 只读 `item`），不写进模型上下文，`session-main.jsonl` 只多这一个键。

### 2. 服务端：`frame` 不能删，只清 `internals`

`src/core/truncate.ts` 的 `rebuildTail()` 会把超长回执替换成 `[result folded]`、把超长消息替换成 `[turn too long, omitted]`，而 `withText()` 只换 `item`、**原样保留 `context`**（[context.ts:64-69](C:/Cortico/Cortico-main/src/protocol/open-responses/context.ts:64)）。那样 `start/chars` 就指向被替换后的短文本。

**但 `context.frame` 不是控制台专用数据**：`requeueUndelivered()` 用 session 记录上的 `context.frame.events[].cursor` 判断哪些外部事件已经投递过、重启后不再补投（[loop.ts:918-923](C:/Cortico/Cortico-main/src/core/loop.ts:918)）。清掉它会让重启后重复投递同一批事件。所以：

- `context.frame` **一律不动**。补投逻辑只读 `events[].cursor`，不读 `start / chars`；所以偏移失效不会波及补投，只需前端自己在越界时降级。
- 只有本次新增、且没有其他消费者的 `context.internals`，在文本被替换时清掉：

```ts
// rebuildTail 替换 item 文本处
if (entry.context.internals) delete entry.context.internals;
```

前端另有兜底：`windowText()` 校验 `start + chars <= text.length`，越界即视引用失效，整段显示并标 `S.evwinStale`。这条兜底同时覆盖"回执被折叠、`frame` 故意保留"的情形。

### 3. 前端：三种形态，一个组件

`src/web/client/features/live/timeline.ts`：

**形态 A —— 完整窗口**（非 `inUser`，最常见）。三条记录拼成一个单元：

1. `renderWorld()` 拿到带 `context.internals` 的 user 消息 → 照常建节点，登记 `pendingPrompts = { entry, node }`，本轮不落盘。
2. `renderToolCall()` 遇到 `isEventFrame()` → 建窗口卡：头部时间先留 `—`，吸收 `pendingPrompts`（`appendChild` 移动节点，不重建，打字机与监听都不用重来），提示数立即可算。把窗口卡登记进 `windowByCall.set(call_id, win)`。
3. `renderToolResult()` 拿到同 `call_id` 的回执 → 从 `entry.context.frame?.events` 取事件、算时间、填头部、填事件区。
   - 回执没有 `frame`（`MISSING_RESULT_RESTART`、配对修复）→ 事件区显示 `S.evwinNoMeta`，其余照常，**不抛错**。

**形态 B —— `inUser` 模式**。没有 evframe 调用，两段都在同一条 user 消息上：`renderWorld()` 见 `context.frame?.events?.length > 0` 就直接建完整窗口（提示段 + 事件段），走同一个组件。

**形态 C —— 内部唤醒**（无事件）。**不建窗口**，落成普通 USER 块，头部加一条可 hover 的摘要条：`HH:MM:SS · 0 条事件 · N 条提示`，时间取 `internals[0].ts`（缺席则 `context.ts`，再缺席 `—`）。三处（§3、边界表、Success Criteria）统一按这一条。

落单规则：`pendingPrompts` 在**任何非窗口记录**到达时、`rebuild()` 末尾、以及所有早退分支之前统一 flush 成形态 C 的 USER 块。

**浮层**（三种形态共用）：
- 挂 `document.body`，`position: fixed`，位置由头部元素的 `getBoundingClientRect()` 算。
- **能力检查**：`typeof el.getBoundingClientRect === 'function'` 才做定位；否则降级为静态块——形态 A/B 挂在窗口卡内，形态 C 挂在那条 USER 块的摘要条之后。测试桩走降级这条，内容与复制逻辑照常可断言。
- `mouseenter` 开、`mouseleave` 150ms 后关、点击固定；按 `Escape` 关闭，或滚动容器 `.tlscroll` 触发 `scroll` 事件时关闭。
- **生命周期**：所有监听挂 `{ signal }`，延迟关闭的定时器句柄存在闭包里。两处收尾，缺一不可：
  - `signal` abort（卸载／路由离开）：移除 body 上的面板、清定时器。
  - `rebuild()` 入口（fork 视图每 3 秒轮询一次，[fork.ts:153](C:/Cortico/Cortico-main/src/web/client/features/live/fork.ts:153)）：先关面板、清定时器、清 `pendingPrompts`／`windowByCall`，再 `inner.replaceChildren()`。否则面板的锚点节点在新一轮里已被替换，浮层会悬在空处。
- 两组：**事件** `hh:mm:ss · source · [type] · N 字 · 首行预览`；**提示** `[kind] hh:mm:ss · N 字` + `▾` 展开全文 + `copy` 复制。
- 复制与展开共用一个 `windowText(entry, refs)`：事件组传 `(outputEntry, outputEntry.context.frame.events)`，提示组传 `(userEntry, userEntry.context.internals)`。两组数据不在同一条记录上，签名必须带 `refs`。
- kind 用原始标识（`gesture` / `memory`），不本地化——调试面板要对回代码。

### 4. 字符串与样式

- `strings.ts`：`zh` 与 `en` 各加 8 条 —— `evwinSummary(events, prompts)`、`evwinEvents`、`evwinPrompts`、`evwinNoPrompts`、`evwinNoMeta`、`evwinStale`、`evwinCopy`、`evwinCopied`。
- `styles.css`：`.evwin` 头部（与 `.ghead` 同级密度）、`.evpop` 面板（沿用主题变量）、`.evpop-row` 的等宽时间列。

### 5. 边界

| 情形 | 行为 |
|---|---|
| 内部唤醒（无帧） | 普通 USER 块 + 可 hover 摘要条；时间取 `internals[0].ts` → `context.ts` → `—` |
| `inUser` 模式 | 同一条消息建完整窗口，按"提示 → 事件"两段，不重复 |
| 回执不带 `frame`（补回执 / 修配对） | 事件区显示 `S.evwinNoMeta`，提示区照常，不抛错 |
| 文本被 `rebuildTail()` 替换 | 只清 `internals`（`frame` 不动，补投逻辑要用）；前端 `start+chars` 越界则整段显示并标"引用已失效" |
| `ephemeral` 记录 | 头部标 `ephemeral`；它会被 `dropEphemeral()` 清掉，下次重画自然消失 |
| 超长提示（memory 400+ 字） | 浮层默认 2 行，`▾` 展开；复制永远给全文 |
| 迷你 DOM 桩（无 `getBoundingClientRect`） | 浮层降级为卡内静态块，内容与复制照常可测 |
| 时间线卸载 / 路由离开 | abort 时移除 body 上的面板、清定时器、监听随 `signal` 归零 |
| fork 视图 | 同一套渲染，`banner`/`header` 不受影响 |

## Success Criteria

- 一次外部唤醒在时间线上是**一个**单元，头部显示 `hh:mm:ss · N 条事件 · M 条提示`；`N` 来自回执的 `context.frame.events`，`M` 来自 user 记录的 `context.internals`。
- hover 头部出浮层；提示每条带 kind、时间、字数，可展开、可一键复制。
- 复制内容与该轮注入文本逐字相同——**比对对象是合并消息里该 ref 的 `[start, start+chars)` 区间**（`session-main.jsonl` 里那条 user 消息），不是事件库原文。
- 内部唤醒显示为普通 USER 块 + 摘要条，不被吞、不与后一条串行。
- 回执缺 `frame`、或文本被折叠替换时，界面只降级不抛错。
- `f.session`、`f.messages`、`rebuild()`、`append()` 四条入口/路径渲染一致。
- 上线前后 `session-main.jsonl` 的新增键只有 `context.internals`；`item`、前缀、token 估算、模型请求体零变化。
- `pnpm typecheck && pnpm typecheck:web && pnpm vitest run tests/web/feature-live.test.ts tests/core` 全绿。
